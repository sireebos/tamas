### **7. DATABASE & DATA PERSISTENCE**

#### Database Engine
- **SQLite Database:**
  - File-based, stored in AppData
  - Path: `%APPDATA%/RestaurantManager/restaurant.db`
  - Auto-created if missing
  - Persistent across sessions

#### Database Entities
- **Users Table:** Stores user accounts, roles, departments
- **Orders Table:** Order records with status, payment method, totals
- **OrderItems Table:** Line items within orders (linking to inventory)
- **MenuItems Table:** Optional menu database (not actively used)
- **InventoryItems Table:** Inventory stock tracking
- **InventoryLogs Table:** History of quantity changes
- **Categories Table:** Item category definitions
- **Departments Table:** Staff department definitions
- **UserDepartments Table:** Many-to-many user-department links
- **CategoryDepartments Table:** Many-to-many category-department links
- **SyncLogs Table:** Tracks changes for sync purposes
- **BrandingSettings Table:** Single-row settings storage

#### Automatic Migrations
- **Schema Upgrades:**
  - Automatically runs on startup
  - Creates new tables if missing
  - Adds missing columns to existing tables
  - Handles legacy column renames (MenuItemId → InventoryItemId)
  - Adds PaymentMethod column to Orders
  - Adds ReceiptHeader/Footer to BrandingSettings
  - Adds ShowDemoLogin, TrademarkText, etc.
  
- **Seed Data (On First Run):**
  - 6 Demo users (dev, admin, chef, waiter, bartender, cashier)
  - 4 Menu items (Burger, Salad, Pasta, Coffee)
  - 22 Inventory items (proteins, produce, dry goods, beverages, dairy)
  - 7 Categories (Proteins, Produce, Dry Goods, Beverages, Dairy, Spices, Supplies)
  - 3 Departments (Eatery/Restaurant, Lounge, Shawarma Spot)

#### Data Relationships
- **One-to-Many:**
  - Order → OrderItems (cascade delete)
  - InventoryItem → InventoryLogs
  - Department → UserDepartments (cascade delete)
  - Category → CategoryDepartments (cascade delete)
  
- **Many-to-Many:**
  - User ↔ Department (via UserDepartment)
  - Category ↔ Department (via CategoryDepartment)
  
- **Foreign Keys:**
  - All foreign key relationships enforced
  - Cascade delete on dependent records
  - Unique constraints on key fields (Email, OrderNumber, UserDepartment combo, CategoryDepartment combo)

#### Data Indexing
- **Performance Optimizations:**
  - Index on Order.OrderNumber (unique)
  - Index on Order.CreatedAt
  - Index on User.Email (unique)
  - Index on UserDepartment (UserId, DepartmentId) - unique
  - Index on CategoryDepartment (CategoryId, DepartmentId) - unique

#### Sync System (Infrastructure Ready)
- **SyncService:**
  - Tracks pending changes in SyncLogs
  - Processes offline changes when online
  - Fetches latest data from server
  - Handles orders, inventory, menu items
  - Base URL: http://localhost:8000/api
  - Health check endpoint
  - Sync endpoints: /sync, /orders, /inventory, /menu-items

- **OnStartup in App.xaml.cs:**
  - Initialize database context
  - Create all service instances
  - Run database migrations
  - Seed demo data if needed
  - Show main window or login window
  - Handle global exceptions
  
- **Service Injection:**
  - Global static instances (App.OrderService, etc.)
  - Available throughout application
  - Dependency initialized once

#### Error Handling
- **Global Exception Handler:**
  - Catches unhandled exceptions
  - Shows error dialog
  - Logs to temp file (RestaurantManager_Error.log)
  - Allows application recovery
  
- **Local Try-Catch:**
  - Service call failures handled gracefully
  - User-friendly error messages
  - Status message display

#### Database Context
- **RestaurantDbContext:**
  - Extends DbContext
  - Configures SQLite connection
  - Defines all entity DbSets
  - Manages migrations
  
- **Configuration:**
  - One-to-many relationships defined
  - Indexes created for performance
  - Foreign key constraints
  - Delete behaviors (cascade, set null)

#### Data Binding
- **XAML Binding:**

  - Visibility binding for conditional UI
  
- **Code-Behind Updates:**
